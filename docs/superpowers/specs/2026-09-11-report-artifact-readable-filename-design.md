# Человекочитаемое имя отчёта — design

## Цель

Итоговые HTML и PDF должны называться по номеру и названию закупки из карточки
TenderPlan, а не по внутреннему UUID бинарного хранилища.

## Источник данных

- номер: `analysis_run.tender_meta.tender_number`;
- название: `analysis_run.tender_meta.title`;
- оба значения уже входят в `tender_report_model_v2.procurement` как `number`
  и `subject`.

Название не берётся из вывода Codex и не меняет семантику 27 полей.

## Формат

При наличии названия:

```text
Анализ закупки <номер> — <название TenderPlan>.html
Анализ закупки <номер> — <название TenderPlan>.pdf
```

Если название отсутствует, остаётся `Анализ закупки <номер>`. Если номер
отсутствует, используется `без номера`.

## Безопасность имени

Из номера и названия удаляются управляющие и запрещённые для Windows символы,
повторяющиеся пробелы схлопываются, конечные точки и пробелы удаляются. Базовое
имя ограничивается 180 символами; номер и префикс сохраняются, сокращается
только название.

## Граница изменения

Меняется только Code-нода `Сгенерировать HTML1` в Report Generation. Нода
`Проверить PDF artifact` уже наследует имя HTML и заменяет расширение на `.pdf`.
Промежуточный multipart alias `index.html`, содержимое отчёта, 27 FINAL полей,
источники и подключения workflow не меняются.

## Проверка

- filename содержит номер и название TenderPlan;
- опасные символы отсутствуют;
- длинное название ограничивается без потери номера;
- пустое название даёт имя только по номеру;
- итоговый PDF наследует тот же base name;
- граф и credentials workflow остаются неизменными.
